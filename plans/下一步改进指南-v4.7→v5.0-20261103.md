## 2. W1 — 治理收尾（P1/P2，纯代码，离线可验证）

### T-50｜`prefer` 真正跳过后端（R1，本版唯一 P1 代码任务）

- **现状**：`POST /solve {"route":"auto","prefer":"pure"}` 里 `prefer` 只是提示，`solver/route.py` 的决策输出 `action=solve,prefer=pure` 后，`backends.BackendRouter` 仍按配置顺序跑完整条后端链——"纯协议优先"在纯协议未配置时会直接落到浏览器，违背 route=auto 的成本语义。
- **改法（最小改动，不重构）**：
  1. `BackendRouter.solve(...)` 增加可选参数 `skip: frozenset[str] = frozenset()`；命中 skip 集合的后端直接跳过（记一条 `cfsolve_backend_skipped_total{backend,reason=prefer}` 指标，可见即可，不做新表）。
  2. `solver/service.py` 的 handler：`route=auto` 决策结果为 `solve` 时，把 `prefer=pure` 翻译成 `skip={"camoufox","flaresolverr","pydoll"}` 中**除了链上第一个 pure 系后端以外**的集合；`prefer=browser` 则 skip 纯协议后端。
  3. `docs/API.md` 契约补一段：`prefer` 在什么组合下生效、什么时候是 no-op（例如 pure 系后端一个都没配）。
- **验收标准**：
  - 新用例（改前必红）：`test_prefer_pure_skips_browser_backends` —— 配 cfsolve+camoufox 双后端，`prefer=pure` 时 camoufox 后端 0 次调用；`test_prefer_browser_skips_pure_backend` 同理反向。
  - 不传 `prefer`（或 route 非 auto）时行为与 v4.7 逐字节一致（回归用例沿用现有 311 个）。
  - `/metrics` 出现 skipped 计数。
- **风险**：L2。skip 集合可能把"唯一可用后端"也跳掉 → 约束：**skip 后链为空则忽略 prefer 全链重跑**，并打 WARN。
- **回滚**：单 commit，`git revert` 即可；参数带默认值，旧调用方零感知。

### T-51｜超大 body 返回 `413`（N5，需先定契约）

- **现状**：`do_POST` 超大 body 走 `invalid-request`（400）。客户端重试语义错：400 = 请求坏了不该重试，413 = 可以换小请求。
- **改法（严格三步，顺序不可颠倒）**：
  1. **先改契约**：`docs/API.md` 新增错误码 `payload-too-large`（413），写明阈值来源（现有 `--max-body-bytes`，默认值不变）。
  2. `solver/errors.py` 注册新 code；`STATUS_BY_CODE` 映射 413。
  3. `service.py` 的 body 大小检查改抛新错误；**保留 `url = ""` 提前绑定**（N-14 的教训：早退路径必须可审计）。
- **验收标准**：新用例 `test_oversized_body_returns_413_and_is_audited`（改前必红，同时断言审计 JSONL 里有这条）；现有 400 系用例不回归；E2E 套件补一条 413 断言。
- **风险**：L3（公共契约）。Go 客户端 `gocfsolve` 对 4xx 一律不重试，无行为破坏；但文档必须先行。
- **回滚**：契约 commit 与行为 commit 分开，可只回滚行为。

### T-52｜`/detect` 同步对齐 413（半小时量级，跟 T-51 同 commit）

- `/detect` 的 body 检查与 `/solve` 共用路径，验证一遍即可；若独立实现则对齐同一错误码。

## 3. W2 — 长稳与真机证据（受预算约束，先排期后执行）

> **红线**：真机预算剩 ~14 次；**累计失败 ≥5 次立即全停**（policy §2）。两条任务共享预算，**先跑 T-53（不吃真机预算），再跑 T-54（预算 ≤12 次）**。

### T-53｜A3 稳态命中率 24h soak（N1）

- **目标**：拿到 `cache_hits / (hits + solves)` 的稳态数字，回答"缓存到底省了多少浏览器"。
- **做法**：本机起 4 worker（compose）+ `--prewarm`，用 `scripts/loadtest.py --mode hot/share` 定时采样 + `scripts/soak.py`，跑 **24h**；采样间隔 5min，落 `plans/证据/v5-hit-rate-24h.jsonl` + summary。
- **验收标准**：
  - summary JSON 含 `hit_rate_steady`（剔除首 1h 冷启动）、句柄曲线（Δ ≤ +50，对照 T-45 基线）、RSS 曲线（回落或持平）。
  - 期间 0 崩溃；`/health` 全程 ready。
  - hit_rate 数字无论高低**如实记录**；低于预期时归因写进 summary 的 `limitations`（比如目标域多样性太高），**不许调 TTL 凑数**。
- **风险**：长跑期间 Windows 更新/休眠会打断 → 建议关休眠或用 `powercfg` 固定；soak 脚本需支持断点续采（已有 `soak.py` 基础，加 `--resume`）。

### T-54｜G1 同站双臂 A/B：route=auto 的真实收益（N2）

- **目标**：把 V12/V13 的单点对照升级成有统计意义的对照表。
- **做法**：固定 2–3 个站点（建议 steamdb.info + udemy + canva，均为 V30 已验证过、成功率高且未提分的站），A 组带 `route=auto`、B 组不带，各 **10 次**（3 站 × 20 = 60 次请求 ≈ 求解次数约 2–3 次/站，真机预算 ≤12）。
- **验收标准**：
  - `plans/证据/v5-route-ab.json`：每站两组的 P50/P90 求解耗时、求解次数、`no_challenge` 命中率。
  - 结论三选一，**写进 README 的核心结论表**：① route=auto 显著更快（x 秒 vs y 秒）② 无盾站节省 100% 求解 ③ 与预期不符（如实记录）。
- **停止条件**：同一站连续 2 次 403/挑战页 → 换站，不硬打（R9b 的教训：同站连打会提分）。

## 4. W3 — 测试卫生与发版

### T-55｜测试卫生：autouse fixture 统一关 `SqliteStore`（R14，P3）

- **现状**：一批用例构造 `SqliteStore` 后没 `close()`，`ResourceWarning: unclosed database` 100+ 条，把 pytest warning 区撑爆，掩盖真信号（N-15 当时就是靠 warning 区发现的——**这个信号通道不能被污染**）。
- **改法**：`tests/conftest.py` 加 autouse fixture，跟踪测试期间创建的 `SqliteStore` 并在 teardown 统一 `close()`；不改任何用例本体。
- **验收标准**：`pytest -W error::ResourceWarning` 退出 0（或 warning 数从 100+ 降到个位数并记录剩余项归因）。
- **风险**：L1，纯测试侧。

### T-56｜`service.py` 继续下沉（R7，P3，**每步必须 311+ 全绿**）

- **改法**：沿用 v4.6 的成功模式（probe.py / auth.py 已拆出），按"请求解析 / 路由决策 / 后端执行"三块继续下沉，**每块一个 commit、原样再导出、拆完即跑 `run.ps1 verify`**。
- **边界**：目标不是凑行数，是让单文件回到 <800 行规范；若某一块拆分会导致大面积 import 重排（回归风险 > 收益），**停下来在 workflow_status §7 记录"评估后不做"**，这是合法结论。

### T-57｜发版 v5.0.0

1. CHANGELOG 写 5.0.0 段（主题：治理收尾 + 收益实证，无 breaking change——413 是新增契约，400 系不删）
2. `docs/项目规格.md` 版本号、§1 规模假设复核；`docs/00-索引.md` 计数对齐 findings
3. findings 回填本轮新缺陷（若有）；`node scripts/validate-findings.mjs` exit 0
4. docker-compose 镜像 tag 对齐 `5.0.0`；本机真构建一次（对照 v4.7 流程）
5. **独立审查 3 轮**（`claude -p` 独立进程，只喂 diff 不喂结论），最终 Approve 才打 tag
6. tag `v5.0.0` + 推送 master（禁止 force push）
