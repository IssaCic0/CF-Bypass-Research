# plans/ — 计划与指南的专用目录

本目录**只放"怎么做"的文档**，不放研究结论、不放代码、不放数据。

## 目录约定

| 路径 | 内容 |
|---|---|
| `下一步改进指南.md` | 当前主施工图纸（v3.0 → **v4.0 路由闭环 + 治理收口 + 缓存/观测升级**），任务卡 + TDD 清单 + 验收门禁（2026-11-01，基线 `d5a5f53`） |
| `archive/下一步改进指南-v2.5→v3.0-20261101.md` | 上一版（17 张卡只落地 1 张，结论勿再引用，任务卡清算见新版 §2） |
| `archive/下一步改进指南-v1.1→v2.5-20261101.md` | 更早一版（大部分已落地，结论勿再引用） |
| `证据/` | 验收时"已验证"的原始输出落地处（压测日志、before/after 对比、命令输出） |
| `状态/` | 状态文件（任务契约、验证日志、审查轮次、剩余风险）的归属地 |

## 与 `docs/` 的分工

- `docs/` = **是什么**（架构、接口契约、研究结论、运维手册）
- `plans/` = **接下来做什么**（迭代计划、任务分解、验收标准、证据）

单一事实源是 `docs/项目规格.md`（见指南 §15）。任何"结论被推翻"必须改正文并留痕，不允许只在行内加注记。

## 新增一份计划的命名规则

`plans/<动作>-<对象>-v<起版本>→v<止版本>.md`，例如：
`plans/吞吐升级-v2.5→v3.0.md`。
