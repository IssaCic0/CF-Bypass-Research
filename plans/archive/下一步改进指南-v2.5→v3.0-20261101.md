## 0. 本版与上一版的关系（先读这个）

上一版规划的 v2.5 吞吐主线，**大部分已经在实际代码里落地了**。本版不是重写计划，而是：

1. **清算**：逐项对照上一版任务卡，标出已落地 / 未落地（带代码行号证据）；

**结论先行**：当前仓库已经是一个"带鉴权、有测试、多后端可切换、可多进程扩容"的可部署服务。
距离"敢上生产"还差两层：**客户端自愈**（T-09/T-10，403 后不会自动重解）和**工程化护栏**（CI/Docker/统一入口/项目规格文档）。

## 3. 第一性原理：v3.0 的优先级为什么这么排

拆到底，这个系统的价值链是：

```
业务请求 → [缓存命中?] →(命中)→ 回放 1.3s → 200
                    └→(未命中/失效)→ 求解 16-20s → 回放
```

两个还没堵住的洞，都在**失效分支**上：

1. **回放层的失效是静默的**（T-10）：`cf_clearance` 因 IP/UA/TTL 漂移失效时，目标站返回 403 或挑战页，而 Go 客户端**原样透传**——业务侧看起来像"渠道挂了"，实际上只要重解一次就好。这是**唯一还在请求路径上等着咬人的缺陷**。
2. **冷路径的并发浪费**（T-09）：N 个并发打到同一个冷域 → N 次 /solve。有共享缓存后多进程场景已缓解，但单机多协程仍会制造 N 倍无效请求。

**对比之下**：CI/Docker/统一入口不改变任何运行时行为，但决定"改动敢不敢合、环境能不能一键起"。它们不性感，但是 v3.0 收口的硬前提。

**仍然不做的事**（延续上一版纪律）：
- ❌ sync→async 重写核心（风险远大于收益）
- ❌ 无证据调大 ttl / 牺牲成功率换速度
- ❌ 引入 prometheus_client/loguru 等可避免依赖
- ❌ 为 E1 好看关共享缓存
- ❌ T-24 探针、T-25 uTLS、T-26 多引擎调度：维持 P3，遇实测需要才做

## 4. 根因级问题清单（v3.0 新增/延续）

> 格式：**现象 → 证据 → 根因 → 影响 → 修法**。P0=上线阻塞，P1=主流程高概率故障，P2=体验/维护。

### P0-1｜回放失效不自愈：403/挑战页原样透传 【CRITICAL·生产咬人项】

- **证据**：`gocfsolve/cfsolve.go:381` `DoWith` 直接返回响应，无状态码检查、无 `cf-mitigated` 头识别、不失效缓存、不触发重解。
- **根因**：v2 波次里 T-10 被排在 W4，随 W3 提前完成而悬空。
- **影响**：cookie 失效后（换出口、TTL 到期、CF 侧提前作废），业务侧**稳定拿到 403 直到缓存自然过期**（最长 `--ttl` 上限）。这是最可能被当成"服务挂了"上报的故障。
- **修法**：**T-10**（见 §6 任务卡）。

### P1-1｜并发缓存未命中打穿求解服务（thundering herd）

- **证据**：`gocfsolve/cfsolve.go` 的 `Get` 无 per-host singleflight；并发冷域 → N 次 `/solve`。
- **影响**：多进程场景被共享缓存缓解，但单进程内多 goroutine 仍制造 N 倍浏览器占用。
- **修法**：**T-09**（零依赖 per-host 单飞，`plans/archive` 旧版 D3 已定方案）。

### P1-2｜无 CI：174+17 项测试没有回归保护

- **证据**：`.github/` 不存在。
- **影响**：任何人（包括后续 AI 会话）改动后若不手动跑测试，破坏会静默进入 master。CI 里禁止真实联网（守卫实验卫生规范）。
- **修法**：**T-19**。

### P1-3｜`参考的结果计划指南.md`（单一状态源）被工作区删除

- **证据**：`git status` 显示 ` D "参考的结果计划指南.md"`；git HEAD 中尚存 501 行（含 Phase B 全部实施记录、验证日志、Next Gate 待决策项）。
- **影响**：跨会话上下文丢失；`docs/00-索引.md:54` 与 skill 仍指向它。
- **修法**：**C6**（恢复 + 归档到正确位置，见 §6）。

### P1-4｜geoip 仍关闭，求解成功率"没有余量"

- **证据**：`service.py:172` `kwargs = {"headless": headless, "geoip": False}`。
- **影响**：延续上一版 P1-5 的判断——V-1 96% 是在 geoip 关闭下测的，扩站后余量不足会直接体现为失败率。**但开启是否提升成功率未知，必须 A/B 实测决定，不许拍脑袋**。
- **修法**：**T-14**（遵守 §8 实验卫生预算）。

### P2-1｜`service.py` 1704 行，超项目 800 行规范 2 倍

- **证据**：`wc -l solver/service.py` = 1704。职责块：HTTP Handler（鉴权/路由/检测端点）、Solver（worker 生命周期/队列/准入）、缓存装配、代理池装配、prewarm 装配、CLI 参数（`--help` 文本即 60+ 行）。
- **根因**：v2 五个波次全部按"在现有函数内增补"执行（上一版禁区条款的正确结果），行数自然膨胀。
- **影响**：定位代码变慢、AI 会话读取成本高；但**它没有坏**——174 项测试全绿即证明行为受控。
- **修法**：**T-27（最小拆分，L2 风险，可选）**：只搬不写——把 `_handle_detect*`（约 1451-1520 行）搬到 `solver/detect_endpoint.py`，把 `metrics_text` 搬到已有模块，CLI `build_arg_parser` 抽成纯函数便于测试。**禁止**改任何公共签名、禁止拆 Solver 类。预期净效果：service.py 降到 ~1400 行，风险极低。若不愿承担任何回归风险，此项可跳过（明确降级为 P3）。

### P2-2｜文档层过期与失同步（详见 §7）

- service.py 行数、"无鉴权"描述（旧版指南 §3.1 已全错）、`docs/最终方案与实现结果.md:121` 仍写 `--host 0.0.0.0` 且**该命令没有 token 提示**（服务端已默认鉴权，照抄文档启动会 401）。
- 修法：**C1–C5**（§6）。

### P2-3｜研究脚本维护性遗留

- `scripts/analyze.py` 未使用导入（`json`/`sys`）等上一版 P2-5 清单项；`node-shim`、`go-jseng`、`go-replay` 属研究产物。
- 修法：C3 顺手清理 + §6 归档决策（保留为"CF 版本变更探针"的原型，不删）。

## 8. 实验卫生规范（延续上一版 §20，仍然强制）

**预算：总计 50 次真实过盾请求**（V-1 剩余额度 + 本期 T-14/E 批次共用，不重复申请）。

| 批次 | 用途 | 次数 | 闸门 |
|---|---|---|---|
| A | T-14 geoip A/B（3 站 × geoip on/off） | 9 | on/off 成功率对照才有结论 |
| B | E1/E3 压测（共享缓存验证） | 20 | 先 `--dry-run` 核对 |
| 预留 | 手工排查 | 21 | — |

硬性规则（与上一版 §20.2 完全一致，逐条仍有效）：
1. 只发 GET 首页；不登入、不提交、不并发打同一站；
2. 同站串行、间隔 ≥30s；
3. 每站先打一次无 cookie 基线；
4. **累计失败 ≥5 次 → 立即停止全部实验**，写"IP 可能已被提分"，隔 24h 再评估，不许换 IP 立刻重试；
5. 每次请求落 `plans/证据/exp-<日期>-<批次>.log`，clearance 值脱敏（只写长度）；
6. 实验脚本必须支持 `--dry-run`；
7. CI 永不执行真实联网实验。

**T-14 结论写入**：`docs/实验-geoip对齐.md`；若 geoip 无收益或需要额外 MMDB 依赖（**先查 camoufox 官方文档确认，不许猜**），默认维持关闭并在 findings 里记 `rejected` 或 `needs_validation`。

## 10. 风险、回滚与停止条件

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| T-10 重解风暴（大量域同时失效） | 中 | 中（浏览器被打满） | 单飞去重 + `WithRevalidate(false)` 开关 + 每 client 全局重解并发上限（建议 2） |
| T-10 读 body 破坏响应流 | 中 | 高（静默错数据） | 用例 #4 强制断言 body 完整性；只在状态码/头部可疑时才 peek |
| T-09 单飞死锁（leader 慢、等待者堆积） | 低 | 高 | 用例 #10 + 单飞 map 带超时兜底（等 ≤ 求解 timeout+5s） |
| CI 在 Windows 专属代码上误报 | 中 | 低 | CI 只跑 Linux；Windows 特有路径（icacls 等）由本地测试覆盖，CI 跳过标记 `@pytest.mark.windows` |
| T-14 开 geoip 引入新依赖或外部请求 | 中 | 中 | 先查文档确认；有外部请求直接否决（研究纪律） |
| 压测烧 IP 信誉 | 中 | 中 | §8 预算 + `--dry-run` 先行 + 失败 ≥5 即停 |
| 拆分（T-27）引入回归 | 低 | 中 | 排 W4 最后、可选、只搬不改签名、174 项测试全绿为准 |
| C6 恢复文件与现有 plans/README 冲突 | 低 | 低 | 状态文件放 `plans/状态/`，plans/README 加一行指向 |

**回滚原则**：每张卡独立可回滚；T-10/T-09 都带开关（`WithRevalidate` / 单飞可禁用），出问题先关开关再排查。

3. 同一卡两次尝试无实质进展；

## 附录 B：术语

- **单飞（singleflight）**：同 key 并发请求合并为一次上游调用，其余等待结果。
- **自愈重解（revalidate）**：回放遇 403/挑战页时自动失效缓存并重解一次。
- **E3（防假吞吐）**：多 worker 吞吐必须以"同域不重复求解"为前提验证。
- **实验卫生**：对真实站点请求的预算、节奏与停止条件约束（§8）。
