## 1. 定位

**它是什么**：一个自托管的「Cloudflare 凭证获取与回放」服务。
输入一个 URL，输出一份可回放的凭证（`cf_clearance` cookie + 当时的 `User-Agent`），
让调用方（网关/采集器）能用普通 HTTP 请求穿过 CF 的机器人校验。

**它不是什么**：

| 不是 | 原因 |
|---|---|
| 通用反爬绕过平台 | 只对 **Cloudflare（及 AWS WAF 令牌）** 有实测过的解法；DataDome / PerimeterX / Kasada 等一律明确拒绝（`route=auto` 会在探测阶段就返回 `unsupported-provider`） |
| 通用爬虫 | 不发批量抓取、不做链接发现、不存页面内容 |
| 匿名代理池 | 代理只用于"让求解与回放在同一出口"，不提供匿名性 |
| 有界面的产品 | **没有 UI**（只有 JSON API 与 Prometheus 文本）。可观测性靠 `/health`、`/stats`、`/metrics` 与 CLI 工具 |
| 高并发平台 | 单进程**串行**求解（浏览器 API 绑线程）。要吞吐只能加进程 |

**规模假设（决定设计取舍）**：稳态 ≈0.08 QPS、并发求解 ≤8/进程、缓存域数 ≤4096。
据此明确**不引入**：消息队列、Redis、K8s、异步任务协议、多租户计费。

## 2. 架构拓扑

```
                 ┌──────────────── 调用方（new-api / 采集器 / Go 客户端）────────────────┐
                 │  POST /solve            GET /health   POST|GET /detect   GET /metrics │
                 └────────┬──────────────────────┬───────────────┬──────────────┬─────────┘
                          │                      │               │              │
┌─────────────────────────▼──────────────────────▼───────────────▼──────────────▼─────────┐
│ HTTP 层（service.Handler，ThreadingHTTPServer）                                          │
│  · Bearer 鉴权（compare_digest）                                                        │
│  · **入口 SSRF 守卫**（与后端无关，选后端之前执行）                                       │
│  · route=auto：探测 → 决策（skip / solve / reject）                                       │
│  · 探测独立准入闸门（--max-detect）                                                       │
└─────────────────────────┬───────────────────────────────────────────────────────────────┘
                          │
┌─────────────────────────▼───────────────────────────────────────────────────────────────┐
│ 路由层（backends.BackendRouter，**治理挂在这里**）                                        │
│  · 有序链：cfsolve（纯协议）→ pydoll → Camoufox（本地浏览器）→ FlareSolverr               │
│  · 每个后端共享：缓存查询/写入、inflight 准入、按后端与按域计数                              │
│  · 终止性错误（参数错/未鉴权/队列满）立刻上抛，不 fallback                                  │
│  · 总预算按墙钟 deadline 切分给各后端（不会让某后端吃掉整个 budget）                        │
└─────────────────────────┬───────────────────────────────────────────────────────────────┘
                          │
┌─────────────────────────▼─────────────┐   ┌────────────────────────────────────────────┐
│ Solver（单 worker 线程 + 有界队列）     │   │ 缓存层（solver/cache.py）                    │
│  · 浏览器只活在该线程（Playwright 绑线程）│   │  · SqliteStore(WAL)：默认，多进程共享         │
│  · inflight 信号量，满即 429            │◄──┤  · FileStore：降级（逃生门）                 │
│  · worker 自愈：启动失败指数退避重拉      │   │  · MemoryStore：兜底                        │
│  · 缓存键 = 域名 + 出口标识              │   │  · 加密：Fernet + PBKDF2(token, salt)       │
└─────────────────────────┬─────────────┘   └────────────────────────────────────────────┘
                          │
        ┌─────────────────┴──────────────────┐
        │ 外部依赖（都是"可选但影响成败"的）      │
        │  · Camoufox 二进制（必须 fetch）      │
        │  · cfsolve 二进制 + profile（纯协议）  │
        │  · Chrome（pydoll）                  │
        └────────────────────────────────────┘
```

**关键不可变量（违反即失效，代码里都有对应断言）**：

1. **同出口**：求解与回放必须同一出口 IP。缓存键必须含出口标识（`--egress-id` / 代理池）。
2. **同 UA**：`cf_clearance` 绑 UA。回放时客户端必须用求解时的 UA（Go 客户端强制覆盖）。
3. **时效 ≈30 分钟**：以 cookie 自带的 `expires` 为准，且不超过 `--ttl`。
4. **按域隔离**：不同域的凭证不混用。

## 3. 接口契约（摘要，全文见 `docs/API.md`）

| 端点 | 鉴权 | 作用 | 关键契约 |
|---|---|---|---|
| `POST /solve` | Bearer | 取凭证 | 求解失败也是 **HTTP 200 + `ok:false`**（`error_code` 区分）；请求级错误才是 4xx/5xx |
| `GET /health` | 公开（精简）/ Bearer（全量） | 三态健康 | `state ∈ ready\|starting\|degraded`，`503` 表示不可用 |
| `GET /stats` | Bearer | `/health` 的兼容别名 | 字段与 `/health` 一致 |
| `POST /detect`、`GET /detect?url=` | Bearer | **只探测不求解** | 一次普通 GET；逐跳 SSRF 复检；结果按域短 TTL 缓存（`fresh=1` 跳过） |
| `GET /metrics` | Bearer | Prometheus 文本 | 计数与直方图；按域指标只保留 top-20（防基数爆炸） |
| `POST /shutdown` | Bearer + **仅回环** | 优雅退出 | 先停收新连接 → 等在途请求（≤10s）→ 再关；必要时 `--allow-remote-shutdown` |

`/solve` 的 `route` 参数（v4.0+）：`fixed`（默认，v3 行为）/ `auto` / `direct` / `pure` / `browser`。
**不传 `route` 时不会产生任何额外探测请求**（专用用例锁死）。

错误码表见 `docs/API.md`；`stage` 字段用于定位失败环节（`validate/admit/navigate/wait/detect/solve/internal`）。

| `--prewarm` / `--prewarm-file` | 空 | 保活目标（逗号分隔 / 一行一个） |
| `--prewarm-interval` | `60` | 保活扫描间隔（秒） |
| `--renew-before` | `300` | 剩余寿命低于该值提前续期（应大于单次求解耗时） |
| `--engine` | `camoufox` | `camoufox` / `cloakbrowser`（专有二进制）/ `patchright` |

| `--flaresolverr` | 空 | 兜底后端地址（自托管） |

## 5. 凭证模型（安全边界）

| 对象 | 存放位置 | 保护手段 | 已知限制 |
|---|---|---|---|
| `CF_SOLVE_TOKEN` | `./.env`（首启生成，0600）或环境变量 | `O_CREAT\|O_EXCL` 独占创建；日志只打 SHA256 指纹前 12 位 | Windows 上 `chmod 0600` 对 NTFS ACL 无效（已在 API 文档写明） |
| 缓存中的 `cf_clearance` | 落盘缓存（SQLite BLOB） | 应用层 Fernet 加密；密钥 = PBKDF2(token, salt.bin, 200k) | **换 token 即作废旧缓存**（这是特性不是缺陷）；盐丢失 = 全部缓存不可读 |
| 代理凭据 | 进程内存（`--proxy`） | 报错信息里一律脱敏（只报"无法解析（凭据已隐去）"） | 会出现在启动命令行里（`ps` 可见）——生产建议用环境变量或配置文件注入 |
| 回放 cookie | 进程内存 / 调用方持有 | 服务端不落盘、日志只打长度 | 调用方拿到后需自行保管 |

**明文红线**：仓库、日志、`/metrics`、`evidence/` 里**不得**出现 clearance 值、token、cookie 内容。
`evidence/` 只允许写长度与指纹（有专门用例 `test_store_encrypts_at_rest` 守着）。

## 7. 已知限制（按影响排序）

| # | 限制 | 影响 | 缓解 |
|---|---|---|---|
| ~~L1~~ | ~~多进程同时抢同一新域各解一次~~ → **v4.4 已修**：`claims` 表抢占（`try_claim`/`release_claim`），抢不到的进程等缓存 | — | 实测 burst 从 12 次求解降到 **3 次/3 轮**（1 次/轮） |
| L2 | `route=auto` 的 `prefer=pure\|browser` 只是提示 | 不能强制跳过后端 | 后端顺序由配置决定（cfsolve 默认排第一） |
| L3 | `route=auto` 每次探测 +0.5s | 冷请求变慢 | 已按域缓存 300s（`--detect-cache-ttl`） |
| ~~L4~~ | ~~Docker 镜像未经构建验证~~ → **v4.4 已实测**：构建成功 1.61GB、容器 5s 就绪、端点与优雅退出全验 | 仅在本机 Docker Desktop(linux) 上跑过 | K8s/其他发行版未验证；镜像未做瘦身 |
| L5 | CI 只跑 Linux | Windows 专属行为（SO_REUSEADDR/NTFS 权限）无自动回归 | 本地 `run.ps1 verify` 必跑 |
| L6 | `engines.py` 覆盖率 57% | cloakbrowser/patchright 未真机验证 | 缺依赖时"启动即失败"有测试兜住 |
| L7 | `service.py` ~2000 行 | 阅读成本高 | 已降级为 P3（拆分风险 > 收益） |
| L8 | Windows 上 chmod 不生效 | 凭证文件权限弱于 POSIX | 用 NTFS ACL 或容器部署 |
| L9 | 入口守卫的两种拒绝语义容易混淆（400 vs 502） | 排查时会把「域名拼错」误判成「被安全策略拦住」 | 见 §7 末尾对照表 |

### 入口守卫的两种拒绝语义（别混）

| 情况 | 返回 | 语义 | 该做什么 |
|---|---|---|---|
| 目标解析到私网/回环/保留地址 | `400 invalid-request` | **策略性拒绝**：这是 SSRF 跳板 | 换公网目标；联调加 `--allow-private-hosts` |
| 域名解析不出来（拼错 / NXDOMAIN） | `502 transport` | **传输层失败，可重试**（实测 DNS 会瞬时失败） | 先确认域名拼写；重试一次 |

> 实测教训：自审时用一个不存在的域名做「后端是否被调用」的测试，请求在入口就 502 了，
> 后端当然一次没被调用 —— 差点误判成「治理没生效」。

## 8. 决策索引

完整决策记录见 `plans/下一步改进指南.md` 附录 C 与 ICM（topic `decisions-CF-Bypass-Research`）。
关键几条：

| 编号 | 决策 | 一句话理由 |
|---|---|---|
| S-1/C-1/C-2/C-3 | 落盘缓存 + Fernet + 单机多进程共享 | 吞吐只能靠加进程，而加进程的前提是共享缓存 |
| A-1 | token 首启自动生成 | 杜绝"部署完忘了配鉴权" |
| V-1/D-4 | 真机请求预算 + 停止条件 | 出口 IP 信誉是这套系统最贵的资源 |
| D-1 | v4.0 只做四波次（止血→新能力→缓存观测→工程化） | 先缝治理裂缝，再谈新能力 |
| D-2 | 缓存换 SQLite(WAL) | mtime 淘汰跨进程语义模糊、purge O(n)、无按域统计 |
| D-3 | 删研究产物（node-shim/go-jseng/go-replay） | 不在主链路，结论保留在 findings |
| v4.1 | 治理从 `Solver.solve` 上提到**入口 + 路由层** | 否则配了任何额外后端，守卫/缓存/准入/指标全部被绕过（已实测复现） |
| 被否决 | Redis / 异步任务协议 / 拆 Solver / uTLS 兜底 | 需求强度（≈0.08 QPS）撑不起复杂度 |

## 附：怎么判断"这个系统现在是好的"

```bash
.\run.ps1 verify     # Python 全量测试 + 覆盖率门槛 80% + Go vet/-race + findings 校验
                    # （具体条数以命令实际输出为准；本文不写死数字，避免一加测试就漂移）
.\run.ps1 smoke      # 起服务 → /health ready → /detect → SSRF 守卫
.\run.ps1 bench      # 离线压测 hot/cold/share
python scripts/doctor.py   # 环境自检（含真实启动一次）
```

四项全绿 + `evidence/` 里对应任务卡有证据文件 = 这个系统当前是好的。
