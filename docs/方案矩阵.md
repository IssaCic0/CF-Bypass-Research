# 方案矩阵：四种过盾路线怎么选

> 本仓库支持**纯协议**与**真实浏览器**两大类，共四条可切换的路线。
> 结论先行：**浏览器路线通过率最高（实测 96%），纯协议最省资源但要额外准备 profile；
> 二者可以串成"纯协议优先、失败回落浏览器"的链条。**

> 实测数据见 **`docs/AB实测-三种过盾方法.md`**（2026-11-01：Camoufox 3/3 @18.7s；
> pydoll 2/3 @74.5s；cfsolve 0/3 因自带 profile 不匹配）。

## 二、决策树（按成本从低到高）

```
要拿什么？
├─ cf_clearance（页面级豁免）
│   ├─ 只是自己的号偶尔要用 → 人工过一次盾，把 cookie+UA 存下来 → go-replay 零依赖回放
│   ├─ 要自动化、且能接受 Rust 构建 → ① cfsolve（纯协议）+ 录 profile
│   └─ 要自动化、不想碰 Rust → ② Camoufox（默认，实测最稳）
└─ Turnstile / reCAPTCHA v3 的一次性 token
    ├─ cfsolve 也支持（--sitekey + --blank-page）→ 仍是纯协议
    └─ 或 ②/③/④ 任一浏览器引擎（本仓库 want=turnstile / recaptcha_v3）
```

**推荐生产配置（本仓库默认就支持）**：

```
后端优先级：cfsolve（纯协议） → Camoufox（浏览器） → FlareSolverr（自托管兜底）
```

纯协议命中时几乎零成本；profile 过期或被拒时自动回落到浏览器，用户无感。
配置方式：`--cfsolve-bin <challenge> --cfsolve-profile <profile.json>`（见 `docs/纯协议-cfsolve.md`）。

## 三、必须知道的三条硬约束（任何路线都逃不掉）

1. **同出口 IP**：`cf_clearance` 绑求解时的出口 IP。换 IP 回放 = 静默 403。
   → 本仓库用 `--egress-id` / `--proxy` + 一致性哈希粘性，并把出口写进缓存键。
2. **同 UA**：profile / 浏览器给出的 UA 必须原样回放。`gocfsolve` 强制覆盖 UA。
3. **时效**：约 30 分钟（以 cookie 自带 `expires` 为准）。到期前用 `--prewarm` 续期。

## 四、"纯协议"到底指什么（三种完全不同的东西，别混）

| 说法 | 实际含义 | 本仓库结论 |
|---|---|---|
| 纯算（离线算 token） | 不接触任何浏览器，纯算法推导 | ❌ 已证伪：挑战 VM 每轮重混淆 + 绑运行时 |
| 纯 JS 引擎 | 自己起 goja/jsdom 跑挑战脚本 | ❌ 实测语法层能跑通，但环境不自洽 → 拿不到凭证 |
| **纯协议（录制回放式）** | 用**录制好的真实浏览器快照**回答指纹质询 + 离线完成挑战密码学 | ✅ **可行**（cfsolve 走这条），但 profile 是消耗品 |

差别在"环境从哪来"：前两者**现场编造**环境，第三种**重放**一份真实环境。

## 六、切换方式速查

```bash
# ① 纯协议（需先构建 cfsolve，见 docs/纯协议-cfsolve.md）
python solver/service.py --cfsolve-bin /path/to/challenge \
    --cfsolve-profile /path/to/profiles/safari-26-ios.json

# ② Camoufox（默认）
python solver/service.py --browser-os windows

# ③ CloakBrowser（需先 pip install cloakbrowser；二进制按需下载）
pip install cloakbrowser && python solver/service.py --engine cloakbrowser

# ④ patchright
pip install patchright && patchright install chromium
python solver/service.py --engine patchright
```

引擎缺失时服务**启动即失败**并打印安装命令，不会静默退回别的引擎（否则你会以为在跑 A、其实在跑 B）。
