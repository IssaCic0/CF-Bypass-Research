# 部署：容器与多 worker

> 面向"要跑起来"的人。项目**没有生产环境清单**（无服务器/云凭证），所以这里给的是
> 可复现的部署方式 + 回滚方式，而不是"我们的线上部署步骤"。

---

## 1. 三种部署形态（按吞吐选）

| 形态 | 适用 | 命令 | 吞吐 |
|---|---|---|---|
| 单进程前台 | 联调、单域保活 | `.\run.ps1 start` | 串行，≈1 次求解/20s |
| 多进程 + 共享缓存 | **默认推荐**（单机扩容） | `scripts/run-pool.ps1 -Count 4 -CacheDir <dir>` | ≈N 倍（N=进程数） |
| 容器（compose） | 需要隔离/可编排 | `docker compose up -d` | ≈N 倍（3 worker） |

**为什么必须多进程而不是多线程**：Camoufox/Playwright 的 sync API **绑定创建它的线程**，
一个进程里只能有一个 worker 线程在求解。想加吞吐只能加进程。

**为什么多进程必须共享缓存目录**：不同进程各解一次同一个域 = 扩容等于白扩。
所有 worker 必须共用 `--cache-dir` 与同一个 token（token 相同 → 派生同一把加密密钥）。

## 2. 多进程（Windows/Linux 通用）

```powershell
# 4 个 worker（端口 8878..8881），共用缓存目录与同一个 token
pwsh scripts/run-pool.ps1 -Count 4 -CacheDir "$env:LOCALAPPDATA\cfsolve\cache"

# 可选：保活（把"贵操作"挪出请求路径）
pwsh scripts/run-pool.ps1 -Count 4 -Prewarm "steamdb.info,glassdoor.co.uk" -RenewBefore 300
```

启动后自检：

```powershell
.\run.ps1 doctor -Port 8878          # 环境 + 真起一次服务
curl http://127.0.0.1:8878/health    # 期望 state=ready
# 关键：各 worker 的 cache_backend 必须**完全一致**
curl http://127.0.0.1:8879/health | Select-String cache_backend
```

Go 侧用 `cfsolve.NewPool` 接（按域一致性哈希 + 失败摘除 + 冷却回归）：

```go
pool, _ := cfsolve.NewPool(
    []string{"http://127.0.0.1:8878", "http://127.0.0.1:8879"},
    cfsolve.WithPoolToken(token),
    cfsolve.WithPoolMaxFailures(2),
    cfsolve.WithPoolDownDuration(30*time.Second),
    cfsolve.WithPoolHealthProbe(30*time.Second),   // 能发现 503+ready:false
)
defer pool.Close()
```

## 3. 容器

```bash
docker compose up -d --build       # 3 worker，共用 solver-data 卷
docker compose ps                  # 看健康状态
docker compose logs -f solver-1
```

⚠️ **状态**：`Dockerfile` / `docker-compose.yml` 已写好但**未在本机构建验证**
（开发机的 Docker daemon 未运行）。首次构建时可能需要按目标发行版调整
`apt-get install` 的包名（Camoufox 是打过补丁的 Firefox，需要 GTK/ALSA/X11 运行库）。

镜像里的两个刻意设计：

1. **`python -m camoufox fetch` 在 build 阶段执行** —— 放到运行期会导致"镜像能起、一求就挂"
   （首次求解时联网下载几百 MB，直接超时）；
2. **非 root 用户运行** —— 会拉起浏览器进程，root 身份放大一切提权面。

## 4. 热更新（本地语义）

本项目没有生产环境，这里的"热更新"指**本机多进程滚动重启**：

```bash
# 1) 记录当前版本与配置
git rev-parse HEAD; grep -c . .env

# 2) 逐个重启 worker（不要同时停，否则会全站 503）
for p in 8878 8879 8880 8881; do
  .\run.ps1 stop -Port $p
  .\run.ps1 start -Port $p &
  curl -fsS http://127.0.0.1:$p/health || { echo "起不来，回滚"; break; }
done

# 3) 更新后冒烟
.\run.ps1 smoke -Port 8878
```

**回滚**：`git checkout <上一版本 tag>` 后按上面同一流程重启；缓存无需清理
（换 token 才会作废旧缓存；代码回滚不影响已加密的条目结构，SQLite 与 FileStore 可并存）。

## 5. 常见故障对照

| 现象 | 原因 | 处理 |
|---|---|---|
| `/health` 一直 `starting` | camoufox 二进制没 fetch | `python -m camoufox fetch` |
| `/health` `degraded` + `browser-unavailable` | 浏览器进程崩了 | 自动指数退避重拉；持续出现看 `last_error` |
| 端口起不来（Windows） | 端口被占 或 SO_REUSEADDR 串台 | `netstat -ano \| findstr :8878` 找到并停掉 |
| 多 worker 各解一次 | `--cache-dir` 没指向同一目录，或 token 不同 | 两者必须一致 |
| 401 | 没带 `Authorization: Bearer` | token 在 `./.env`（首启生成） |
| 回放稳定 403 | 凭证失效（换出口/TTL/CF 作废） | Go 客户端会自愈重解（`WithRevalidate`）；服务端看 `routed_by` |
